## A. 확정된 결정 (ADR)

### ADR-001 · 백엔드를 NestJS 자체 구현에서 Payload CMS로 교체

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락**
초기안은 Next.js(FE) + NestJS(BE) 분리 구조였다. 8주 로드맵을 산출한 뒤 항목을 분해해보니,
차별화에 기여하는 작업은 2주치였고 나머지 6주는 인증·미디어 업로드·어드민 CRUD UI·권한·
드래프트/버전 등 **이미 풀린 문제를 다시 푸는 작업**이었다.

동시에 이 서비스의 실질적 제약은 기술이 아니라 **콘텐츠 생산 속도**임이 분명해졌다.
물건은 최소 1개월 사용해야 쓸 수 있고 여행은 실제로 다녀와야 한다.
인프라에 쓴 8주는 그동안 쌓였을 리뷰 16건과 맞바꾸는 것이다.

**대안 검토**

| 안 | 판단 |
|---|---|
| NestJS 자체 구현 | 8주. 포트폴리오 가치는 있으나 사업 목표와 어긋남 |
| WordPress + ACF Pro | 2~3주. 데이터 모델 90% 커버 가능하나 **커스텀 테마 개발이 PHP로 2~3주**, 필터 인터랙션이 계속 거슬림 |
| **Next.js + Payload** ✅ | 4주. 디자인 픽셀 일치 유지, TS 단일 언어, Local API로 HTTP 홉 제거 |

**결정** Next.js 15 + Payload CMS 3.86.x + PostgreSQL, 단일 앱 단일 배포.

**결과**
- 로드맵 8주 → **4주**
- **어드민이 W1에 완성**되어 W2부터 콘텐츠 집필 병행 가능 (이전 안은 W4)
- 모노레포·`packages/types`·BFF 프록시·REST 컨트롤러 40여 개 폐기
- 데이터 모델과 발행 검증 규칙 등 **기획 판단은 그대로 유효**

**감수하는 리스크**
- Payload가 2025-06 Figma에 인수됨. MIT 라이선스·저장소 유지, v3 릴리스 지속 중이나 장기 방향은 Figma 전략에 종속
- v4 개발 중 (관리자 UI 개편). **v3로 시작하고 v4는 안정화 후 이전**
- 완화책: 데이터는 자체 Postgres에 있으므로 최악의 경우 SQL째로 이전 가능

### ADR-002 · 리뷰를 5종 다형 타입으로 설계

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락**
시안 rev.2에서 서비스가 "살림 블로그"에서 "라이프스타일 매거진"으로 확장되며
여행·숙소·맛집·비교가 들어왔다. 물건과 경험은 **데이터 성격이 다르다.**
물건은 `구매가·사용기간·재구매의사`, 여행은 `총경비·박수·재방문의사`다.

**대안 검토**

| 안 | 판단 |
|---|---|
| 타입별 테이블 완전 분리 | ❌ 목록·검색·태그·댓글을 5번 UNION. 통합 피드가 핵심 UI인데 치명적 |
| 단일 테이블 전체 nullable | ❌ 컬럼 절반이 항상 NULL, 제약 검증 불가 |
| **단일 컬렉션 + 판별자 + 조건부 필드 그룹** ✅ | 목록은 단순, 어드민은 타입별로 자동 분기 |

**결정** `type: PRODUCT | TRIP | STAY | PLACE | COMPARISON`.
공통 축을 일반화: `purchaseType→acquisitionType`, `usageMonths→experienceScale+Unit`, `buyAgain→wouldRepeat`.
타입 고유 필드는 Payload `admin.condition`으로 조건부 노출.

**결과** Postgres 어댑터가 group/array를 자동 정규화하므로 스키마 품질은 테이블 분리와 동등.
별도 어드민 화면 개발 불필요.

### ADR-003 · 표시 문자열을 DB에 저장하지 않는다

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락** 시안에 `"직접 예약"`, `"3박 숙박"`, `"재숙박 의사 있음"` 같은 완성된 문자열이 하드코딩돼 있었다.
그대로 저장하면 같은 개념이 표현별로 파편화되고(실제로 `재구매/재방문/재숙박` 3종이 발생), 필터가 깨진다.

**결정** `(type, acquisitionType, experienceUnit)`에서 `src/lib/labels.ts`의 매핑으로 파생시킨다.

### ADR-004 · 기획의 약속을 발행 검증으로 강제한다

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락** "단점을 숨기지 않는다", "총경비·동선을 기록한다"는 카피는
강제되지 않으면 3개월 뒤 반드시 지켜지지 않는다. 바쁘면 가장 먼저 생략되는 항목들이다.

**결정** `validatePublish` 훅에서 발행 시 차단한다.

| 규칙 | 근거 |
|---|---|
| 단점 최소 1개 | 서비스 정체성 (원칙 #4) |
| `TRIP` 총경비 + 동선 필수 | 여행 섹션 리드 문구가 약속한 것 |
| `STAY` 1박 요금 필수 | 동일 |
| `COMPARISON` pick 정확히 1개 | "우리의 선택"이 비교 콘텐츠의 결론 |
| 상황 태그 1개 이상 | 필터에서 누락 방지 |
| 커버 이미지 alt 필수 | 접근성을 데이터 제약으로 |

**규칙 완화 시 이 문서에 근거를 남긴다.**

### ADR-005 · 다크 모드를 MVP에 포함한다

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락** 시안 rev.2에 다크 모드가 이미 들어와 있다.
연기하면 그동안 작성된 컴포넌트에 리터럴 색이 쌓이고, 나중에 전부 걷어내야 한다.

**결정** W2에 전면 적용. 축소 대상에서 제외한다.
CSS 변수 재정의 방식이라 컴포넌트가 `var()`만 참조하면 추가 비용이 거의 없다.
CI에 리터럴 HEX 금지 lint를 걸어 회귀를 막는다.

### ADR-006 · 리뷰 상세 URL을 타입과 무관하게 통일한다

**결정일** 2026-08-04 · **상태** ✅ 확정

**맥락** `/travel/stays/[slug]` 같은 중첩 구조를 검토했으나,
